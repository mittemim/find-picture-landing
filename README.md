# Картина без происхождения

Учебный мини-сайт на Next.js: закрытая галерея принимает первичные обращения по делу о картине без происхождения. Посетитель оставляет контактное лицо, телефон для связи и ожидание по вознаграждению за наводку.

## Границы мини-проекта

Одна страница с тремя секциями:

- **«Витрина дела»** — представление картины и краткая сюжетная справка.
- **«Основания для контакта»** — пояснение, с какой наводкой можно обратиться в галерею.
- **«Первичный запрос»** — форма обращения и результат отправки.

Страница задумана как один экран на широком дисплее. На небольших экранах секции располагаются последовательно с прокруткой.

## Форма

Только три пользовательских поля:

| Поле | Назначение | Базовая проверка |
| --- | --- | --- |
| Контактное лицо | Как обращаться к посетителю | Обязательная строка, от 2 до 100 символов после удаления пробелов по краям |
| Телефон для связи | Номер для обратной связи | Обязательный номер, от 10 до 15 цифр; допустимы начальный `+`, пробелы, скобки и дефисы |
| Вознаграждение за наводку | Ожидаемая сумма в рублях | Обязательная неотрицательная целая сумма в пределах безопасного целого числа JavaScript; `0` означает без вознаграждения |

Клиентская валидация показывает ошибки рядом с полями. Во время отправки повторная отправка блокируется. После ответа посетитель видит подтверждение приёма или понятное сообщение об ошибке.

## Приём и хранение обращения

- Next.js с App Router и TypeScript.
- API-роут `POST /api/requests` принимает JSON с полями `contactPerson`, `phone`, `reward`.
- Серверная Zod-схема независимо проверяет все три поля и отклоняет неизвестные поля.
- Невалидный запрос возвращает `400` и не сохраняется. Успешное сохранение возвращает `201`. Ошибка хранения возвращает `500` без внутренних подробностей.
- Валидная запись сохраняется в локальную SQLite через параметризованный запрос. Серверный обработчик работает в Node.js runtime.
- Файл базы хранится вне публичных файлов сайта и исключается из Git вместе с сопутствующими файлами SQLite.
- Внутренний идентификатор и время создания допустимы как служебные поля базы; пользователь их не заполняет.

## Контрольный просмотр

Node.js-скрипт `scripts/view-requests.mjs` читает сохранённые записи из SQLite и выводит только:

- контактное лицо;
- телефон для связи;
- вознаграждение за наводку.

Идентификаторы, время создания и другие служебные данные в вывод не включаются. Скрипт предназначен для локального контрольного просмотра, отдельная веб-страница со списком обращений не требуется.

## Что не входит

Авторизация, личные кабинеты, админ-панель, загрузка файлов, дополнительные поля формы, поиск по обращениям, уведомления, платежи и выплата вознаграждения, проверка происхождения картины, интеграции с внешними сервисами и публичный продакшен-деплой.

## Критерии готовности

- На странице есть все три секции и форма ровно с тремя пользовательскими полями.
- Клиентская проверка не пропускает очевидно некорректные значения.
- Прямой запрос к API также проходит серверную Zod-валидацию.
- Валидное обращение сохраняется и остаётся в SQLite после перезапуска приложения.
- Невалидное обращение не создаёт запись.
- Контрольный скрипт выводит только три оговорённых поля.
- Секреты, зависимости, сборка и база с контактами не попадают в Git.

## Текущий этап

Первый PR содержит только этот README с границами мини-проекта. Страница, API, Zod-схема, SQLite и контрольный скрипт будут реализованы следующими шагами. Команд запуска приложения на этом этапе нет.

Рабочие ветки именуются `feature/<краткое-описание-на-английском-через-дефисы>`, изменения предлагаются через PR в `main`.
